# REVIEW.md

Review of the starter `app/main.py`. Line numbers refer to the starter file.

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | module, `MongoClient(...)` (L22) | No `tz_aware=True`, so PyMongo returns **naive** datetimes. Comparing them with the aware `IST` datetimes in `compute_overtime` raises `TypeError`; serialising them drops the time zone. | Any punch-out that reuses `compute_overtime` with a stored `punch_in` → 500. | `MongoClient(..., tz_aware=True)`. All instants are aware UTC inside the app. |
| 2 | `compute_late_minutes` (L35) | Builds the shift start with `punch_in.replace(hour=h, minute=m)`, i.e. in whatever zone `punch_in` happens to be in (server local / UTC), not IST, and always on the punch-in's own calendar day. | On a UTC server a 10:15 IST punch-in is 04:45 UTC, so the "shift start" is 09:30 UTC and `late_minutes` is 0. Overnight shift 22:00: a punch-in at 00:30 IST gives 0 instead of 150. | Shift start is computed in IST on the record's attendance date (`shift_window`), which handles the overnight case (R1). |
| 3 | `compute_late_minutes` (L36-37) | Grace check is done on minutes that are already floored: `minutes > 10`. | 09:40:01 → 10 floored minutes → returns 0; expected 10 (R2). Every punch-in from 09:40:01 to 09:40:59 is wrongly on time. | Compare the elapsed time with the grace period exactly (`elapsed > 10 min`), then floor to minutes. |
| 4 | `compute_late_minutes`, `compute_work_hours` | Instants are not truncated to whole seconds before calculating (R1). | 09:40:00.900 must count as 09:40:00; with a correct `> 10:00` check it would be late. Work hours use fractional seconds. | `from_ms` truncates at the boundary; `derived_fields` truncates stored values before computing. |
| 5 | `compute_work_hours` (L41) | `round(x, 2)` on a float: banker's rounding plus binary representation, not half-up (R4). | 09:30:00 → 18:37:30 is 9.125 h → `round` gives **9.12**, expected 9.13. | `Decimal(seconds) / 3600` quantized with `ROUND_HALF_UP`. |
| 6 | `compute_overtime` (L46-47) | (a) No 30-minute minimum (R3). (b) Shift end is placed on the attendance date, which is wrong for overnight shifts (ends the next day). | (a) Out at 18:35 → 5 instead of 0. (b) Sample doc 7 (22:00-06:00, out 06:40 next day) → 1480 minutes instead of 40. | Overtime counted only when ≥ 30; `shift_window` moves an overnight shift's end to the next day. |
| 7 | `EmployeeIn` (L53-60) | No validation at all: `emp_code` pattern, email, lengths, `HH:MM` shift times, real `joined_on` date, `shift_start != shift_end`. | `{"emp_code": "x", "shift_start": "25:99", "joined_on": "2026-02-30"}` → 201. | Pydantic constraints from the contract plus a model validator for equal shift times → 422. |
| 8 | `PunchInIn` (L65-66) | `punched_at: Optional[int]` is lax: `"1783312500000"` (string) and `1783312500000.0` (float) are coerced, seconds (`1783312500`) and absurd values are accepted. `status: str` accepts `ABSENT`, `LEAVE` or anything. | POST with `punched_at: 1783312500` → 201 dated 1970. `status: "ABSENT"` → 201 with a punch time. | `StrictInt` with range 1e11 … 4102444800000; `status` is `Literal["PRESENT","WFH","ON_DUTY"]`. |
| 9 | `health` (L73) | Always 200; never talks to MongoDB. | Stop MongoDB → `/health` still says ok, then every request 500s. | `ping` the server; 503 on any `PyMongoError` (with a 5 s server-selection timeout so it answers quickly). |
| 10 | `create_employee` (L79-83) | Check-then-insert with no unique index: two concurrent creates both pass `find_one` and both insert. | 10 parallel POSTs of the same `emp_code` → several 201s, duplicate employees. | Unique index on `emp_code`; just insert and map `DuplicateKeyError` → 409. |
| 11 | `create_employee` (L82, L85) | `created_at = datetime.now()` is naive local time; PyMongo stores naive values as UTC, so on an IST server the instant is 5:30 h off. The response returns it as an ISO string, not epoch ms. | Response has `"created_at": "2026-10-12T22:15:03.123"`; contract says integer ms. | `datetime.now(UTC)`; converted with `to_ms` in `employee_out`. |
| 12 | `list_employees` (L93) | `skip = page * page_size`: page 1 skips the first page. | 3 employees, `page=1&page_size=2` → returns only the 3rd. | `skip = (page - 1) * page_size`. |
| 13 | `list_employees` (L94) | `total` counts the whole collection, ignoring the department filter (R10). | `?department=Sales` → `total` equals all employees. | `count_documents(query)` with the same filter. |
| 14 | `list_employees` (L95) | No sort (contract: `emp_code` ascending), so order is whatever MongoDB returns and pages can overlap. | Insert EMP3, EMP1, EMP2 → listed in insertion order. | `.sort("emp_code", 1)`, served by the `emp_code` / `(department, emp_code)` indexes. |
| 15 | `list_employees`, `list_attendance` (params) | `page` / `page_size` not bounded (R10). `page_size=0` → `limit(0)` means *no limit* (whole collection); negative `page` → negative skip → 500; `page_size=10000` allowed. | `GET /employees?page_size=0` returns everyone. | `page ≥ 1`, `1 ≤ page_size ≤ 100` via `Query` constraints → 422. |
| 16 | `list_employees` (L95), `list_attendance` | `created_at` / `punch_in` / `punch_out` / `history[].at` are returned as datetimes (ISO strings), not epoch ms; legacy records without `history` / `half_day` come back without them. | Response field types do not match the schema. | `employee_out` / `record_out` build the response explicitly with `to_ms` and the documented defaults. |
| 17 | `punch_in` (L101, L113) | Unknown employee: `emp` is `None` and `emp["shift_start"]` raises. | `{"emp_code": "EMP9999"}` → 500 instead of 404. | `find_employee` raises 404 first. |
| 18 | `punch_in` (L102) | `datetime.fromtimestamp(ms / 1000)` gives a naive **server-local** time; `datetime.now()` likewise. Stored instants are off by the server's UTC offset, or the date is the server's date. Also `if body.punched_at` treats `0` as "now". | On a UTC server, a punch at 02:00 IST on the 7th is dated the 6th. | `from_ms` → aware UTC, truncated to seconds; `utc_now()` when omitted; `is not None`. |
| 19 | `punch_in` (L103) | `date` is the server-local calendar date, not the IST date, and ignores the overnight rule (R1). | Overnight shift, punch at 00:30 IST → dated today instead of yesterday. | `attendance_date()` implements R1 in IST. |
| 20 | `punch_in` (L104-118) | Check-then-insert race: two simultaneous punch-ins both see no record and both insert (no unique index). | 20 parallel identical punch-ins → several 201s and duplicate day records. | Unique index on `(emp_code, date)`; insert directly, `DuplicateKeyError` → 409. |
| 21 | `punch_in` (L119), `list_attendance` (L149) | Exposes MongoDB's `_id` as `id`; the contract says `_id` never appears and records are addressed by `(emp_code, date)`. | Response contains `"id": "6710..."`. | Removed; responses never contain `_id` / `id`. |
| 22 | `list_attendance` (L144-147) | Loads **every** matching document into Python and sorts / paginates in memory. With no index this is a collection scan of ~100k documents per request. | `GET /attendance` takes seconds and lots of memory at 100k records; explain shows `COLLSCAN`. | `find().sort().skip().limit()` in MongoDB, backed by `(date desc, emp_code)`, `(emp_code, date)` and `(status, date desc, emp_code)` indexes. |
| 23 | `list_attendance` (L145) | Sorts by `date` only; the contract also requires `emp_code` ascending as tie-breaker. | Same-day records come back in arbitrary order, so pages are unstable. | Sort `[("date", -1), ("emp_code", 1)]`. |
| 24 | `list_attendance` (params) | No validation: `date_from > date_to` should be 422; malformed dates (`2026-13-01`) and unknown `status` values silently match nothing. | `?date_from=2026-07-08&date_to=2026-07-01` → 200 with an empty list. | `DateStr` / `Status` types, explicit range check → 422. |
| 25 | startup (whole file) | No indexes are created at all, so nothing can be race-safe and every query scans. | `db.attendance_logs.getIndexes()` shows only `_id_`. | `ensure_indexes()` in the FastAPI lifespan, idempotent. |

## Looked at and decided were not defects

* `load_dotenv()` without `override=True` is correct: it never overwrites a variable that is already set, so real environment variables win as the contract requires.
* `IST = timezone(timedelta(hours=5, minutes=30))` is right (IST has no daylight saving).
* Sync `def` endpoints with PyMongo are fine: FastAPI runs them in a thread pool, and `MongoClient` is thread-safe. Moving to Motor/async would not change correctness.
* Keeping `date`, `joined_on` and shift times as strings is deliberate in the data model; `"YYYY-MM-DD"` strings sort and range-compare correctly.
* `status_code=201` on the two create endpoints and the `{"_id": 0}` projection in `list_employees` are correct.
* The default connection string `mongodb://localhost:27017` is only a fallback for local runs; `MONGO_URI` / `MONGO_DB` always come from the environment when set.
